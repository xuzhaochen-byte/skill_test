# 会议纪要生成器

把杂乱的会议原始素材（录音转写、聊天记录、手写笔记）转成一份结构清晰、可直接分发的会议纪要。核心价值是**结构化提取**（决策、待办、风险）和**格式规范化**，而不是简单转述。

## 何时使用

用户提供一段会议相关文本并希望得到整理结果时使用，典型信号：
- "帮我整理 / 总结这段会议记录"
- "把这段转写稿 / 聊天记录变成会议纪要"
- "提取会议里的待办 / action items / TODO"
- "生成一份周会 / 评审会 / 复盘会纪要"

素材可能是：ASR 转写稿（含说话人标签、口语化、重复）、IM 群聊记录、Bug/需求评审讨论、用户随手记的要点。

## 工作流程

### 1. 判断输入形态
先识别素材类型，决定清洗力度：
- **转写稿**：去除口头语（"呃、那个、就是说"）、重复句、寒暄，合并同一说话人的连续发言。
- **聊天记录**：过滤表情/无信息灌水，按话题而非时间线重组。
- **零散笔记**：补全上下文，推断隐含结论，但推断项要标注「（待确认）」。

### 2. 结构化提取
从素材中抽取以下要素，缺失的部分留空而不是编造：

| 要素 | 说明 |
|------|------|
| 会议主题 | 一句话概括 |
| 时间/参会人 | 素材中出现的才填，否则留空 |
| 讨论议题 | 按主题分组，每个议题给出结论而非流水账 |
| 关键决策 | 明确"决定了什么"，附决策依据 |
| 待办事项 | 动作 + 负责人 + 截止时间（Owner/DDL 缺失要显式标注） |
| 风险/待确认 | 未达成一致、有分歧、需后续拍板的点 |

**提取原则**：待办事项是纪要最高价值部分。凡出现"XX 来做 / 下周之前 / 需要跟进"这类语义，都要抽成一条 action item。负责人和截止时间从上下文推断，推断不出就标 `待定`，绝不省略这一列。

### 3. 生成纪要
默认输出规范 Markdown，结构见 [references/output-format.md](references/output-format.md)。若用户要发飞书文档，说明用「使用 lark-doc / lark-sheets skill 完成写入」，本 skill 只负责产出内容。

### 4.（可选）辅助脚本
当素材很长、待办很多，或需要单独交付一份待办清单时，用脚本从生成好的纪要 Markdown 里抽取结构化 action items：

```bash
python3 scripts/extract_action_items.py <纪要文件.md>
```

脚本解析「## 待办事项」章节的表格，输出 CSV（动作/负责人/截止时间/状态）到同目录，便于导入表格或任务系统。这一步是可选的确定性工具，纪要本身由模型直接生成。

## 质量准则

- **结论优先**：每个议题写"得出了什么"，不是"谁说了什么"的逐字记录。
- **不编造**：时间、人名、数字等事实缺失就留空或标 `待确认`，不要臆造。
- **可执行**：待办必须是动词开头的具体动作，能被直接认领。
- **简洁**：一场 1 小时的会，纪要正文控制在一屏左右，细节靠结构而非篇幅。
