# 会议纪要输出格式

生成会议纪要时默认采用以下 Markdown 结构。缺失字段保留标题但内容留空或标注 `待确认`，不要删除整个章节，以便使用者知道有哪些信息缺口。

```markdown
# 会议纪要：<会议主题>

- **时间**：<YYYY-MM-DD HH:MM，缺失则留空>
- **参会人**：<姓名列表，缺失则留空>
- **记录人**：<缺失则留空>

## 一、会议概要
<3~5 句话概括会议目的与核心结论>

## 二、讨论议题
### 议题 1：<议题名>
- 结论：<得出的结论>
- 背景/依据：<为什么这么决定，可选>

### 议题 2：<议题名>
- 结论：...

## 三、关键决策
1. <决策内容> —— 依据：<决策理由>
2. ...

## 四、待办事项
| # | 待办动作 | 负责人 | 截止时间 | 状态 |
|---|---------|--------|---------|------|
| 1 | <动词开头的具体动作> | <姓名/待定> | <YYYY-MM-DD/待定> | 未开始 |
| 2 | ... | ... | ... | 未开始 |

## 五、风险与待确认
- <未达成一致或需后续拍板的点>
```

## 写作要点

- 议题按主题聚合，不要按时间线罗列发言。
- 「待办事项」表格列固定为：待办动作 / 负责人 / 截止时间 / 状态；这样 `extract_action_items.py` 才能正确解析。
- 「关键决策」与「待办事项」区分：决策是"定了什么"，待办是"接下来谁去做什么"。
- 若素材信息量很小（如几句话），可省略「讨论议题」的多级拆分，但保留待办与决策两节。
